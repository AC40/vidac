# Architecture

Vidac is a local-first preparation engine with two clients: a React workspace and a Python CLI. It is a useful first release, not a replacement for a finishing editor.

```text
Browser / CLI / external assistant
             │
      validated commands
             │
   SQLite catalogue + durable job queue
             │
     one locked worker process
       ├─ FFmpeg / ffprobe → proxies, shots, thumbnails, waveforms
       ├─ Ollama (optional) → descriptions, activity segments, edit plans
       ├─ faster-whisper (optional) → speech / word timings
       └─ timeline engine → MP4 review / OTIO / FCPXML / Resolve bundle
```

## Repo layout

| Path | Responsibility |
| --- | --- |
| `apps/web` | React 19, TypeScript, Vite; self-hosted fonts; responsive library/editor UI |
| `packages/core/src/vidac` | Python 3.12+ domain logic, FastAPI, Typer CLI |
| `tests` | Domain, API, job, model-contract, export and FFmpeg integration tests |
| `tests/browser` | Playwright real-browser workflow tests |
| `docs` | Storage, timing, agent workflow and handoff contracts |
| `scripts/dev.py` | Starts the local API and Vite together |

Dependencies are pinned by `uv.lock` and `package-lock.json`. The web production build is served by the same FastAPI process as the API; no Node service is needed at runtime. Python-only wheel installation does not include the web build. Run from this repository or set `VIDAC_WEB_DIST` to an existing build directory.

## Data and storage

- **Assets** are immutable source bytes identified by SHA-256. A path import references the file in place. Browser uploads copy bytes into `uploads/`. A different file with the same hash is not ingested twice. Source paths can change without changing asset identity. Recursive relink jobs match missing originals by size and SHA-256, including renamed files, and preserve clips, revisions and VFR intermediate references. Hashing checks file stability before committing a new path.
- **Clips** are virtual frame ranges into an asset, not separately encoded videos. Every clip also has camera-shot bounds, title, tags, description, favorite state, analysis provenance and a thumbnail. Trimming can extend into that shot's handles but cannot cross its boundary.
- **Edits** contain ordered clip references and explicit source trims. Each save writes a new immutable revision. Optimistic concurrency rejects stale saves instead of overwriting someone else's version.
- **Artifacts** belong to a specific edit revision. Exporting an old revision does not export the current draft by accident.
- **Jobs** persist in SQLite. A workspace file lock allows one consumer. Interrupted jobs are recovered when that consumer restarts. Subprocess cancellation is cooperative; an in-flight model request can take up to its timeout to return.

```text
.vidac/
  library.sqlite3           # catalogue, edits, versions, jobs, FTS index
  settings.json
  worker.lock
  cache/<asset_id>/         # proxy, thumbs, waveform, optional transcript/conform
  uploads/<upload_id>/      # original bytes when using browser upload
  exports/<edit_id>/v<N>/   # generated handoff / review artifacts
  demo/                    # only explicitly requested synthetic sample
```

Keep the workspace database on a local filesystem, preferably SSD. Originals can live on an external disk or mounted NAS. Do not put a live SQLite database on a synced folder or unreliable network share. For backups, stop the server and copy the workspace **and any externally referenced originals**. No cloud sync, backup service, media consolidation or retention policy is implemented.

Proxies and thumbnails can be regenerated by reimporting the exact source; this preserves clip IDs and manual metadata. The application has no destructive media-delete action. Treat uploaded originals as valuable source files, not disposable cache. A VFR conform is regenerable but may also be referenced by an editor; keep it for the life of the edit.

## Preparation pipeline

1. Validate the local path and hash it. Check for an existing asset.
2. Read metadata with ffprobe. If reported average and nominal frame rates differ materially, create a ProRes LT constant-frame-rate editing intermediate. The original remains untouched.
3. Generate a CFR H.264/AAC review proxy. PQ/HLG-tagged media is tone-mapped for review when FFmpeg's `zscale` filter is available; originals are not tone-mapped.
4. Detect camera cuts using FFmpeg's scene-difference filter. Minimum-shot duration suppresses short false positives. Motion, flashes and gradual transitions are not perfectly classified.
5. Without AI, subdivide shots into configurable-duration selects. No semantic understanding is claimed.
6. With a configured image-capable Ollama model, sample up to twelve timestamped images per 30-second shot window. Validate proposed contiguous activity boundaries, then subdivide long activities into selects. Failures retain unclassified selects and emit warnings. Sampling is approximate and can miss short actions.
7. Optionally transcribe speech locally. Transcript text is attached to overlapping selects; the complete word-timed transcript is a cached JSON derivative.
8. Save metadata, thumbnails and search entries transactionally. Source size and modification time must remain stable during import.

The current VFR check is a metadata heuristic, not a full per-frame timestamp audit. If a camera reports misleading rates or erratic timestamps, pre-conform its footage before import. Color/codec support is bounded by the installed FFmpeg build. There is no RAW debayer engine or camera-specific log normalization.

## Timing contract

- Rational frame rates are strings, e.g. `25/1` and `30000/1001`.
- Source positions are integer frames relative to the beginning of the editing asset; source timecode is retained as metadata, not added to these indexes.
- `source_in` is inclusive; `source_out` is exclusive. Never store decimal seconds as the source of truth for a cut.
- Timeline duration is `round((source_out - source_in) / source_fps * timeline_fps)`. It is recomputed during validation, never trusted from an AI response.
- With VFR conformance, clip frames refer to the ProRes editing intermediate. Exports link that intermediate, not the old VFR file under new frame semantics.
- Mixed-rate OTIO preserves source ranges; NLEs may quantize their duration differently. FCPXML uses explicit timeline-frame durations. The Resolve adapter checks returned item durations and warns on differences. Matching source and timeline frame rates is the safest interchange.
- Review rendering uses proxy frame trims, explicit output rate/canvas, letterboxing and a simple CDL-derived LUT. Intermediate shot audio is PCM; AAC is encoded once after concatenation to avoid per-shot encoder delay.

## Model boundary and agent access

Ollama is opt-in and restricted to a loopback HTTP endpoint. Vision and planning models are configured separately. Vidac never pulls Ollama models automatically. Explicitly enabling optional transcription can download its model weights on first use.

Models return Pydantic-validated data, never shell commands. The planner receives at most eighty described candidates. It cannot invent clip IDs, reference arbitrary files, run FFmpeg commands, choose arbitrary filters, or exceed duration limits. A requested AI plan that fails does **not** silently become an offline plan. Vision failures are different: footage remains useful as unclassified selects, with warnings recorded.

An external coding assistant can operate the CLI or HTTP API and submit the same edit-plan JSON. There is no embedded assistant login, hosted API backend, subscription billing integration, MCP server or cloud fallback. See [agent workflow](agent-workflow.md).

## Operational scope

- The API listens on loopback by default. It has host/origin checks and a custom write header to reduce browser-origin attacks, **not user authentication**. Do not expose it directly to a network or the internet.
- One workspace and one consumer; no multi-user authorization, GPU scheduler or distributed queue.
- Full-text token/prefix search, not vector/semantic search. The catalogue UI currently displays up to 1,000 selects per query; the offline planner considers up to 80 ranked candidates.
- Watch folders enqueue files after 15 seconds of stable size/mtime. A copy stalled longer than that may still be incomplete; use atomic moves into the watched folder when possible. Failed imports are visible and retryable.
- UI and API poll instead of using streaming events. Long operations run off the request thread in persistent jobs.
- Four basic look presets, one video track, one source-audio track, hard cuts. No music licensing/search, automatic dialogue edit, transitions, motion graphics, audio ducking, optical flow or full color matching.
- Tauri packaging, embeddings, advanced color workflows, cloud storage and an integrated chat experience are future extensions, not hidden dependencies of this release.
